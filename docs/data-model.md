# FogTrust Data Model

| | |
|---|---|
| Version | 0.1 (Week 1 draft) |
| Author | Member 1 (Identity, Access and Audit) |
| Reviewers | Members 2, 3, 4 |
| Status | Draft for team review. Entities marked *Proposed* are owned by another member, who confirms or changes them. |

The brief requires the data model, roles, input schema, decision/result schema and audit-event
format to be defined **before building screens**. This document covers all five.

---

## 1. Conventions (apply to every table)

| Rule | Why |
|---|---|
| Primary keys for domain objects are **UUIDv4 generated by the server**. Clients never choose IDs. | Brief: "Generate identifiers server-side". Stops ID guessing and enumeration. |
| All timestamps are **UTC**, stored timezone-aware, sent as ISO 8601 (`2026-11-12T09:30:00.123456Z`). | Comparable across nodes; the dashboard converts for display. |
| **Secrets are never stored in plain text.** Passwords use Argon2. High-entropy tokens (enrollment tokens) are stored as SHA-256 hashes. | A database leak does not reveal usable credentials. |
| Public keys are stored as **base64 of the raw 32-byte Ed25519 key** (44 characters). | One unambiguous format for Members 1 and 2. |
| **Private keys never reach the server.** | Only the node can sign as itself. |
| Enumerations are lowercase strings (`active`, `revoked`). | Readable in the database and in JSON. |
| All database access goes through the Django ORM (parameterised queries). No raw SQL with string formatting. | SQL injection. |
| Personal data is minimised: no email, phone or real name is required for any account. | Brief: do not retain unnecessary personal information. |

## 3. Entities

### 3.1 User — `accounts.User` (Member 1)

Extends Django's `AbstractUser`. Created in Week 1 because Django only allows a custom user
model before the first migration.

| Field | Type | Constraints | Notes |
|---|---|---|---|
| id | bigint | PK | Django default; never shown in URLs to non-admins |
| username | varchar(150) | unique, `^[a-zA-Z0-9_.-]{3,150}$` | |
| password | varchar(128) | required | Argon2 hash only |
| role | varchar(16) | `admin` \| `operator` \| `viewer`, default `viewer` | Least privilege by default |
| is_active | bool | default true | Disabled accounts cannot log in |
| last_login | datetime | nullable | Set by Django |
| date_joined | datetime | | Set by Django |

`first_name`, `last_name` and `email` exist on the Django base class but are left empty and
never required.

### 3.2 EnrollmentToken — `nodes.EnrollmentToken` (Member 1)

A one-time secret an admin generates and gives to one new node out of band.

| Field | Type | Constraints | Notes |
|---|---|---|---|
| id | UUID | PK | Shown in the admin UI and audit log instead of the token |
| token_hash | char(64) | unique | SHA-256 hex of the raw token. The raw token is shown **once** on creation and never stored |
| label | varchar(64) | required | e.g. "gateway in lab 2" |
| created_by | FK User | required, admin only | |
| created_at | datetime | | |
| expires_at | datetime | required | Default 15 minutes after creation (configurable) |
| used_at | datetime | nullable | Set atomically on successful enrollment |
| used_by_node | FK Node | nullable, unique | One token, one node |
| cancelled_at | datetime | nullable | Admin can cancel an unused token |

A token is **valid** only if: hash matches, `used_at` is null, `cancelled_at` is null and
`now < expires_at`. Redemption uses a conditional update (`UPDATE ... WHERE used_at IS NULL`)
inside a transaction so two simultaneous requests cannot both use it.

Raw token format: 32 random bytes from `secrets.token_urlsafe(32)` (about 43 characters).

### 3.3 Node — `nodes.Node` (Member 1)

| Field | Type | Constraints | Owner of updates |
|---|---|---|---|
| id | UUID | PK, server-generated at enrollment | M1 |
| name | varchar(64) | unique, `^[a-z0-9][a-z0-9-]{2,63}$` | M1 |
| public_key | char(44) | unique, base64 of 32-byte Ed25519 key | M1 (set once, never changed) |
| key_fingerprint | char(64) | SHA-256 hex of the raw public key | M1 (shown on the dashboard) |
| status | varchar(16) | `active` \| `revoked` | M1 |
| capacity | smallint | 1 to 100 (maximum concurrent tasks) | M1 at enrollment |
| current_load | smallint | 0 to capacity | M3 |
| trust_score | smallint | 0 to 100, initial value set by policy | M3 |
| last_seen_at | datetime | nullable | M2 (accepted heartbeat) |
| last_counter | bigint | default 0 | M2 (replay defence) |
| enrolled_at | datetime | | M1 |
| enrolled_via | FK EnrollmentToken | | M1 |
| revoked_at | datetime | nullable | M1 |
| revoked_by | FK User | nullable (null = automatic revocation) | M1 |
| revoke_reason | varchar(500) | required when revoked | M1 |
| revoke_source | varchar(16) | `manual` \| `automatic`, nullable | M1 |

Rules:
- Revocation is **permanent**. A revoked node must re-enroll with a new token and a new key,
  and gets a new ID. This keeps the history of the old identity intact.
- Every node-authenticated endpoint checks `status == active` **before** any other processing.
- A revoked node is never eligible for task assignment (Member 3 enforces in the scheduler).

## 4. Decision schema (shared by every slice)

Every engine function returns, and every view stores, a decision in this shape. It makes each
warning, score or allow/deny decision explainable and reproducible, as the brief requires.

```json
{
  "decision_id": "6f0e8c1e-7a4b-4f7c-9a3e-1c2d3e4f5a6b",
  "subject_type": "heartbeat",
  "subject_id": "b2c4...node-uuid",
  "decision": "deny",
  "reason_code": "HEARTBEAT_REPLAYED",
  "explanation": "Nonce 9f3a... was already used by this node at 2026-11-12T09:30:00Z.",
  "rules_fired": [
    {"rule": "nonce_unique", "passed": false, "detail": "nonce seen before"},
    {"rule": "timestamp_window", "passed": true, "detail": "skew 1.2 s, limit 30 s"},
    {"rule": "signature_valid", "passed": true, "detail": "Ed25519 OK"}
  ],
  "evidence": {"counter": 41, "last_counter": 41, "nonce_prefix": "9f3a"},
  "engine_name": "replay_guard",
  "engine_version": "1.0.0",
  "policy_version": 3,
  "thresholds": {"timestamp_window_s": 30},
  "request_id": "0b6f...",
  "decided_at": "2026-11-12T09:30:01.204Z",
  "latency_ms": 2.7
}
```

| Field | Rules |
|---|---|
| subject_type | `enrollment` \| `node` \| `heartbeat` \| `task` \| `result` \| `policy` |
| decision | `allow` \| `deny` \| `flag` \| `assign` \| `revoke` \| `score` |
| reason_code | A code from `backend/core/errors.py`, or `OK` for allow |
| explanation | One sentence a human can read on the dashboard. No secrets |
| rules_fired | Every rule that was evaluated, passed or not |
| evidence | Non-secret values that support the decision. Never keys, tokens, plaintext results |
| latency_ms | Measured inside the engine; used for the report's decision-latency numbers |

## 5. Audit event format (Member 1)

### 5.1 Fields

| Field | Type | Notes |
|---|---|---|
| sequence | bigint | PK, auto-increment. Defines chain order |
| event_id | UUID | Public identifier |
| timestamp | datetime | UTC, microseconds |
| actor_type | varchar(16) | `user` \| `node` \| `system` \| `anonymous` |
| actor_id | varchar(64) | Username, node UUID, `system`, or empty for anonymous |
| actor_role | varchar(16) | `admin` \| `operator` \| `viewer` \| `node` \| empty |
| action | varchar(64) | Dotted name from the catalog in 5.4 |
| target_type | varchar(32) | e.g. `node`, `user`, `policy`, `token` |
| target_id | varchar(64) | |
| outcome | varchar(16) | `success` \| `failure` \| `denied` |
| reason_code | varchar(48) | Error code when outcome is not success |
| request_id | UUID | Same ID as the `X-Request-ID` response header |
| source_ip | varchar(45) | Kept for security investigation only (see limitations statement) |
| details | JSON | Redacted (5.5), max 4 KB |
| prev_hash | char(64) | **unique**; `hash` of the previous event, or 64 zeros for the first event |
| hash | char(64) | See 5.2 |

### 5.2 Hash chain

```
canonical = JSON of every field except `hash` (including `sequence`),
            keys sorted, separators (",", ":"), non-ASCII escaped,
            timestamp as ISO 8601 UTC with microseconds and "Z"
hash      = SHA-256( prev_hash + "\n" + canonical )   -> lowercase hex
```

Implemented in `backend/audit/chain.py`. Changing, inserting or deleting any past event changes its
hash, which no longer matches the next event's `prev_hash`. Verification
(`python manage.py verify_audit_chain`, or `POST /api/v1/audit/verify/`) recomputes every hash and
reports the first broken sequence number with one of three problems:

| Problem | Meaning |
|---|---|
| `sequence_gap` | A sequence number is missing: an event was deleted |
| `link_mismatch` | `prev_hash` is not the previous event's hash: an event was replaced or reordered |
| `hash_mismatch` | The event's content no longer matches its own hash: an event was edited |

Each event is written inside an atomic block, and SQLite transactions are `IMMEDIATE`
(`config/settings.py`), so "read the latest event, insert the next one" is one serialised step.
`prev_hash` is also unique, so two events can never link to the same parent and the chain cannot
fork; a write that loses a race is retried.

Known limit: removing the **newest** events from the end of the file leaves a shorter chain that
still verifies. The database triggers block this through SQLite; detecting it after direct file
edits would need the latest hash stored somewhere else (see the limitations statement).

### 5.3 Append-only enforcement

1. **Application:** `AuditEvent.save()` refuses to update an existing row; `delete()` raises.
2. **Database:** SQLite triggers `BEFORE UPDATE` and `BEFORE DELETE` on the audit table call
   `RAISE(ABORT, 'audit log is append-only')`, so even raw SQL or the Django admin cannot edit it.
3. **Detection:** the hash chain catches anything that bypasses 1 and 2 (e.g. editing the file).

### 5.5 Redaction rules

Before an event is written, `details` passes through `redact_details()` (`backend/audit/redaction.py`):

- Any key whose name contains `password`, `passwd`, `secret`, `token`, `private`, `api_key`,
  `apikey`, `authorization`, `cookie`, `session`, `csrf`, `signature`, `proof` or `credential`
  (case-insensitive, at any depth) is replaced with `"[REDACTED]"`.
  Exceptions: `token_id` and `token_label`, which identify a token without revealing it.
- Strings longer than 256 characters are truncated with a `…[truncated]` marker.
- At most 50 keys or list items per level and 4 levels deep; values that are not JSON
  (UUIDs, datetimes) are stored as text.
- If the result is still over 4 KB, it is replaced by `{"_truncated": true, "keys": [...]}`.
- Request bodies are never logged whole. Only the specific fields needed are copied in.
- Enrollment tokens are referenced by `token_id`, never by value.

How to write an event from any slice: `audit.services.log_event()` (see its docstring).
Write failure events **outside** any `transaction.atomic()` block that is about to roll back.

## 6. Input schema (server-side validation)

Global rules, already enforced in `config/settings.py` and `core/exceptions.py`:

| Rule | Value | Error code |
|---|---|---|
| Content type | `application/json` only | `UNSUPPORTED_MEDIA_TYPE` |
| Maximum body size | 256 KB (env `MAX_REQUEST_BODY_BYTES`) | `PAYLOAD_TOO_LARGE` |
| Unparseable JSON | rejected | `MALFORMED_REQUEST` |

Per-field rules (serializers in Weeks 2 and 3; unknown fields are rejected):

| Field | Rule |
|---|---|
| username | 3 to 150 chars, `[a-zA-Z0-9_.-]` |
| password (login) | 1 to 128 chars (length cap stops very long-password DoS on the hasher) |
| password (new) | Django validators: min 10, not common, not all digits, not similar to username |
| role | one of `admin`, `operator`, `viewer` |
| node name | `^[a-z0-9][a-z0-9-]{2,63}$` |
| public_key | base64 that decodes to exactly 32 bytes and loads as an Ed25519 public key |
| enrollment_token | 20 to 128 URL-safe characters |
| proof (enrollment) | base64 that decodes to exactly 64 bytes (Ed25519 signature) |
| capacity | integer 1 to 100 |
| revoke reason | 10 to 500 chars, no control characters |
| any UUID in a URL | must parse as a UUID, otherwise `NOT_FOUND` |
| page_size | 1 to 100 |
